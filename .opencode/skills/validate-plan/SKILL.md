## What I do
- Locate the implementation plan (from path, git history, or user input)
- Read the plan and identify expected changes and success criteria
- Spawn parallel research tasks to verify database changes, code changes, and test coverage
- Run all automated verification commands
- Assess manual verification criteria with clear testing steps
- Think deeply about edge cases, error handling, and regressions
- Generate a comprehensive validation report with pass/fail status
- Compare actual implementation against plan specifications file-by-file
- Document deviations and potential issues

## When to use me
Use this after implementing a plan to verify correctness. Works best after commits are made, as it can analyze git history. Run before merging to catch issues early.
